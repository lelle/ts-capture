# @ts-capture/core

## 0.4.0

### Minor Changes

- [`dfc6fe4`](https://github.com/lelle/ts-capture/commit/dfc6fe49b3367dacc4a94b12716d8f86e2600e66) Thanks [@lelle](https://github.com/lelle)! - `ts-capture apply` now writes through `annotateProject`. A file the tsconfig does not list is type-checked against the project before an annotation is written to it, as the files it lists are; before, its annotations were written unchecked. `infer.cstAware` has no effect any more and prints a warning when set to `false`; it will be removed.

- [`3837b9d`](https://github.com/lelle/ts-capture/commit/3837b9db1e70398519439de8280ff7faa029c249) Thanks [@lelle](https://github.com/lelle)! - `instrumentSource` takes a `program` option: a Program the caller already has, which `instrumentImplicitThis` asks where `this` is implicitly `any`. A caller without a tsconfig, such as the browser, can now observe `this` too.

- [`aefbe20`](https://github.com/lelle/ts-capture/commit/aefbe201b90ddad8e42446d935ff0da7e3fe199f) Thanks [@lelle](https://github.com/lelle)! - There is one applier. `applyTypesToFile`, `applyTypesToFileCst` and `applyTypesToFiles` are deprecated in favour of `annotate` and `annotateProject`; `applyTypesToFile` now runs the same applier as `annotate` instead of the offset-based one, so its output follows the same rules as `ts-capture apply`. The options that only steered the hand-off between the two appliers (`checkerSites`, `stripConflictNotes`, `inferClassFields`) are gone.

- [`fd5c4bd`](https://github.com/lelle/ts-capture/commit/fd5c4bd5b763915b3347c1dee1546e939efa2ac2) Thanks [@lelle](https://github.com/lelle)! - An applier plugin's `apply` may return an `AnnotateResult` (`{ text, skips, telemetry }`), with skip positions relative to the source it was given. `ts-capture apply` then counts what the plugin wrote and lists what it skipped in `--report`. Returning a plain string still works, with nothing to report, and is deprecated.

- [`a5080c8`](https://github.com/lelle/ts-capture/commit/a5080c887b038c746a51a45e57da185a02f5c043) Thanks [@lelle](https://github.com/lelle)! - A position that already has a written type is now a skip with the reason `already-annotated`, at its position, instead of only a count. `annotate` returns it with the other skips, and `apply --report` counts it under "Nothing to add" as before. `ApplySkipReason` has two new values, `already-annotated` and `no-site`.

- [`585185c`](https://github.com/lelle/ts-capture/commit/585185c1203f85332b5a26f6a1db099a4e2695e7) Thanks [@lelle](https://github.com/lelle)! - `ts-capture verify` now has TypeScript compare what the run saw with the type at each position, where the text comparison could not decide. Named and structural types are now settled: on honojs/hono and nestjs/nest the share of written types reported unverifiable falls from about half to about a fifth, and no type that matched before stops matching. New reasons say why the rest cannot be decided (`generic declared type`, `name not in scope`, `declared narrower than observable`, …).

### Patch Changes

- [`cad80a5`](https://github.com/lelle/ts-capture/commit/cad80a5871f0034019ae6cec0d59db2927bf6a53) Thanks [@lelle](https://github.com/lelle)! - `ts-capture apply-bundle` now writes through the same applier as `ts-capture apply`, on syntax alone, so the two follow the same rules.

- [`75d2677`](https://github.com/lelle/ts-capture/commit/75d26774088f2ad2790b21bd99ba4764d97e3c36) Thanks [@lelle](https://github.com/lelle)! - A class field typed from its constructor parameter now goes through the same checks as every other site. With the type-check oracle on (the CLI default), a field TypeScript already infers from the constructor's assignment is left as it is instead of being restated, and a field that is not written is listed in `apply --report` with the reason.

- [`60c2eac`](https://github.com/lelle/ts-capture/commit/60c2eacbc563c8fd01d5070d27d21246ff5b4886) Thanks [@lelle](https://github.com/lelle)! - A callback the run passed `undefined` where TypeScript types it as a function is reported as a contradiction instead of written as `(() => void) | undefined`. The function arm read differently inside a union than on its own, so the disagreement was never seen.

- [`2ce8db8`](https://github.com/lelle/ts-capture/commit/2ce8db83d2e57e0f355196f6b3e128432cca4710) Thanks [@lelle](https://github.com/lelle)! - A variable initialized with a choice between functions, `const compare = asc ? (a: number, b: number) => a - b : (a: number, b: number) => b - a`, is left with the types its functions already have, as a single arrow is. `apply` could write a union of the observed function types over it, with `unknown` for a branch the tests never called.

- [`085191a`](https://github.com/lelle/ts-capture/commit/085191a83542b276acfd6785ed23d1383be9d929) Thanks [@lelle](https://github.com/lelle)! - A function observed as a value is no longer kept alive by the collector. Before, every callback passed through an instrumented function was held for the rest of the run, with the scope it closed over, so a long `register` or dev-server session grew in memory for as long as it ran.

- [`85f4723`](https://github.com/lelle/ts-capture/commit/85f47236c3db6172ef78171aff0e2fdf27635b05) Thanks [@lelle](https://github.com/lelle)! - `apply` judges a site by all its observations together. A variable whose initializer can produce a union (`a ?? b`, a ternary, `.find(...)`) was left untyped when each test worker recorded one branch, even if the branches together covered both. It is now annotated when more than one type was observed, and a site observed many times is listed once in `apply --report`.

- [`3f921d7`](https://github.com/lelle/ts-capture/commit/3f921d73806172542e656a9eb886ce796b5033a2) Thanks [@lelle](https://github.com/lelle)! - A parameter no call passed is no longer written as `: undefined`, which made every later call that passes it a type error. Apply leaves it alone and reports it as `no-information`: "every call left it out".

- [`1da26ec`](https://github.com/lelle/ts-capture/commit/1da26ec8ac40f44ec59843ac69a8ccd5337066e7) Thanks [@lelle](https://github.com/lelle)! - A paren-less arrow whose return type is written while its parameter is not (`xs.forEach(x => x.close())`) now gets its parentheses, `(x): void => …`, instead of the unparseable `x: void => …`.

- [`a287dc0`](https://github.com/lelle/ts-capture/commit/a287dc0d03f95e3e7dff2a76b76fdb455ff6a325) Thanks [@lelle](https://github.com/lelle)! - `node --import @ts-capture/core/register` now writes through the same applier as `ts-capture apply`, on syntax alone, so the two follow the same rules.

- [`63988f6`](https://github.com/lelle/ts-capture/commit/63988f64d2e3f4a6b9d06ee9b0761b1b7bf426ab) Thanks [@lelle](https://github.com/lelle)! - Every observed position `apply` leaves alone now has a reason in `apply --report`. A declaration marked `@ts-capture-ignore` is counted under "Nothing to add" as `marked @ts-capture-ignore`. A variable left for TypeScript to infer says why: its initializer is a function with its own types, passes type arguments or sits in a generic function (the code already says more), or only one branch of its initializer, or only `undefined`, was observed (counted under "Nothing to add" as `left for TypeScript to infer`). `ApplySkipReason` has two new values, `ignored` and `left-to-typescript`.

- [`fd710be`](https://github.com/lelle/ts-capture/commit/fd710be78f85f6eb50674532035a66d70a361f08) Thanks [@lelle](https://github.com/lelle)! - An observation whose position is no place a type can go, typically because the code changed since the run, is now listed in `apply --report` under "No place to write it" instead of being dropped without a word. `apply` no longer hands such entries to a second, offset-based applier.

- [`b159994`](https://github.com/lelle/ts-capture/commit/b15999465b9fdbe2965adace9372de1526ab716d) Thanks [@lelle](https://github.com/lelle)! - Apply no longer writes a second `this` parameter into a function that already declares one (`greet(this: Date, this: Date)`, which does not parse). The entry is skipped as already annotated.

- [`0e4ab1a`](https://github.com/lelle/ts-capture/commit/0e4ab1a49b6c1ec159c6c838df884925ff97df30) Thanks [@lelle](https://github.com/lelle)! - Apply reads a `.tsx` or `.jsx` file as JSX. It read every file as plain TypeScript, so in a component file the code after the first JSX element was misread and its observations were dropped.

- [`901d8ea`](https://github.com/lelle/ts-capture/commit/901d8ea664406418ef095a11571c50f16fecb1c6) Thanks [@lelle](https://github.com/lelle)! - A union of observed types is split at its real arms everywhere: a `|` inside a string literal or inside the class-chain marker (`captureClassHierarchy`) no longer cuts an arm in two.

## 0.3.0

### Minor Changes

- [`d21c07e`](https://github.com/lelle/ts-capture/commit/d21c07eb0eb861c9fce89177a31322c954261933) Thanks [@lelle](https://github.com/lelle)! - New `annotate(text, entries, options)` and `annotateProject({ types, readFile, oracle })` write observed types and return the text together with every skipped entry and its reason, instead of a bare string. ## 0.2.0

### Minor Changes

- [#5](https://github.com/lelle/ts-capture/pull/5) [`0bc7c28`](https://github.com/lelle/ts-capture/commit/0bc7c28e0b212fc11f14384b3d3fb8fce5021085) Thanks [@lelle](https://github.com/lelle)! - New opt-in `infer.aliasRepeatedShapes`: a shape that several annotations in one file spell out is declared once, after the imports, and written as its name at each of them. The declaration is named after the first position that holds the shape, so `product` gives `type Product = { ... }` and an array `products` gives `Product` too; a name the file already uses is passed over. The type-check oracle verifies each annotation with the declaration beside it, and the declaration is written only when an annotation naming it is.

- [#5](https://github.com/lelle/ts-capture/pull/5) [`44e2ef4`](https://github.com/lelle/ts-capture/commit/44e2ef4927ce7a7f17b6b4f2ff3e9567dfe2adc6) Thanks [@lelle](https://github.com/lelle)! - `apply` now says what it did. Every run prints how many annotations were written and how many observed positions were not, by reason; it used to print nothing. `apply --report` lists each of those positions with the observed type and why it was left: the type error it would have introduced (with its code and location, including errors in test files), an observation carrying no type information, a type the file cannot name, or a value outside the type already there.

- [`e3d7de2`](https://github.com/lelle/ts-capture/commit/e3d7de2ddefba00ee53b2316d03c79dfa845b101) Thanks [@lelle](https://github.com/lelle)! - New experimental entry `@ts-capture/core/browser`: the engine without Node. It exports `instrumentSource`, `createObserver` (a collector with the `__tscptr__` hook to hand to instrumented code) and `applyInMemory`, which applies observations to a project read through a `ts.System` you supply and runs the same type-check gate as `ts-capture apply`. `createProjectVerificationContext` takes that system as an optional fourth argument. In a runtime that cannot inspect a promise, a returned promise is followed to see it settle, which marks a rejection as handled. The entry may change in any 0.x release.

- [#7](https://github.com/lelle/ts-capture/pull/7) [`9dd0cfd`](https://github.com/lelle/ts-capture/commit/9dd0cfdeef035e55f4f9e1b4a1b0f4d59be26a92) Thanks [@lelle](https://github.com/lelle)! - `apply --dry-run` now prints what it would change as a unified diff, after the list of files. The docs, the tutorial and the apply-review skill have always called the dry run a diff to read before applying, and it printed only file names. The list of files and the summary lines are unchanged, so a script that reads them keeps working; nothing is written to disk, as before.

- [#5](https://github.com/lelle/ts-capture/pull/5) [`df9815d`](https://github.com/lelle/ts-capture/commit/df9815d4b2855a59b8d44732b98014f9dba618dc) Thanks [@lelle](https://github.com/lelle)! - With literals on, a union of observed literals is written as the in-scope type alias that unites them: `type Status = "active" | "inactive"` in scope turns `status: "active" | "inactive"` into `status: Status`. The alias is used when the observed arms are all of its arms, or at least two of them and exactly one alias holds them; a single observed literal keeps its inline form. Arms that are not literals stay beside the alias (`Status | undefined`), and the rule applies inside object fields and generic arguments. Part of `preferNamedInScope`, which so far matched object shapes only.

- [#5](https://github.com/lelle/ts-capture/pull/5) [`4664ab1`](https://github.com/lelle/ts-capture/commit/4664ab159a4053ff454de7c986a69c1282545d72) Thanks [@lelle](https://github.com/lelle)! - New opt-in `infer.narrowParamShapes`: a parameter's object shape is written with only the properties the function body reads from it. The observed shape is the caller's object, and under a test run that is a fixture, so every key the fixture carried became a requirement on every caller. The whole shape stays wherever the body passes the parameter on, returns it or stores it, and a shape that matches an in-scope type in full is written as that type, as before.

- [#5](https://github.com/lelle/ts-capture/pull/5) [`3c61ec0`](https://github.com/lelle/ts-capture/commit/3c61ec0fbe8e59de9ad37179bd92ae42c7a8a78a) Thanks [@lelle](https://github.com/lelle)! - A function returning a hand-built promise now gets a return type. The runtime keeps returned promises aside and, at each flush, records the value of every one that has fulfilled as `Promise<T>` at the return position; it used to record `Promise<unknown>`, which `apply` drops. A promise's state is read without touching it, so a rejected promise is left exactly as it was and unhandled-rejection reporting is unchanged. Node runtimes only: the browser collector is as before. The Babel runtime and the Vite plugin call the new sweep before flushing.

- [#5](https://github.com/lelle/ts-capture/pull/5) [`8a64d3f`](https://github.com/lelle/ts-capture/commit/8a64d3f12158463f2ca15cc53b112928cf0fa2ef) Thanks [@lelle](https://github.com/lelle)! - A short array of mixed element kinds is observed as a tuple: `[key, value]` holding a string and a number is written `[string, number]` instead of `Array<number | string>`. Arrays of two or three elements qualify when their elements are of more than one kind, with literals widened for the comparison; same-kind and longer arrays stay arrays. At one position, same-arity tuples merge element-wise, and a tuple seen beside an array or a tuple of another length widens back to an array. The Vite browser collector mirrors the rule, and now spaces the element union of a mixed array the way core does.

- [`b5d2455`](https://github.com/lelle/ts-capture/commit/b5d24559804dc95839024f79bb4f9afe614c5a6b) Thanks [@lelle](https://github.com/lelle)! - `ts-capture verify` can now check the types you wrote. Run the tests with `TS_CAPTURE_OBSERVE_ANNOTATED=1` and parameters and return types that already have a type are observed too; `verify` lists them under "Written types", apart from the positions where it checks TypeScript's inference, and `--threshold` then counts only them. `apply` never writes over a type you wrote, with or without the variable. What the text comparison cannot settle, such as a named type the value may well be or a literal type the run widened, is reported as unverifiable rather than as a mismatch. An async return is now compared with what its promise resolved to, and the returns of paren-less arrows and destructured parameters are found.

Object-typed callback parameters are skipped because TypeScript takes them from the array's element type, but the skip went by the method's name: on `cart.lines.find((line) => …)` with `cart` still `any`, nothing was inferred, the observed type was dropped, and `--report` listed the position as "already inferred by TypeScript" while the compiler reported it as implicit `any`. In `class Counter { count; constructor(initial) { this.count = initial; } }`, with `initial` observed as a number, `count` is written `count: number`. The default applier had left the field untyped, because the inference only saw the entries it did not handle itself, and the constructor parameters were never among them.

- [#5](https://github.com/lelle/ts-capture/pull/5) [`044fba2`](https://github.com/lelle/ts-capture/commit/044fba226893412f5b16cdb7447c9c4c7e5854f1) Thanks [@lelle](https://github.com/lelle)! - The collectors decide whether to rewrite the dump from a cheap change counter instead of building the collected output each time. On hono's suite (3944 tests) an instrumented run with the Vite plugin takes about as much CPU as 0.1.0 while now resolving callback types, and wall-clock time is lower. `CollectionContext` gains `revision()`, which changes whenever `getCollectedTypes()` would return something different.

- [#5](https://github.com/lelle/ts-capture/pull/5) [`132e6aa`](https://github.com/lelle/ts-capture/commit/132e6aa4439307991cdebb6bcf49c4d57fc0ba88) Thanks [@lelle](https://github.com/lelle)! - A type first seen at an already-observed position late in a run is now written to the dump. The collectors only rewrote the dump when a new position appeared, so a later `null` or second union member at a known position stayed in memory and never reached `types.json`. Annotations that were silently missing a union member, or dropped because the incomplete type failed the type-check, can now be written.

- [`aeb1fb1`](https://github.com/lelle/ts-capture/commit/aeb1fb173b2debc9a06d9e5d233eef1459e9a907) Thanks [@lelle](https://github.com/lelle)! - The package pages on npm now link to the project site, https://lelle.github.io/ts-capture/, which plays the README recording, shows what ts-capture wrote into real projects and has a playground that runs in the browser.

- [`451bd0b`](https://github.com/lelle/ts-capture/commit/451bd0b1b8a392e6a4f0c7633d047aae79ce4f61) Thanks [@lelle](https://github.com/lelle)! - Instrumented code now keeps the names of its functions and classes. A function or class that takes its name from where it is defined, such as `const handler = () => …`, `const handler = (): Response => …`, `{ onClick: () => … }`, `class K { field = () => … }` or `const Model = class {}`, lost that name once the instrumenter wrapped it in a call, so `handler.name` was `""` during the run. - [#5](https://github.com/lelle/ts-capture/pull/5) [`1835f45`](https://github.com/lelle/ts-capture/commit/1835f45bfb0987ff1cea2e4b3813e983b0a6b2b1) Thanks [@lelle](https://github.com/lelle)! - `apply` no longer drops a local, class field or callback annotation because an edit earlier in the same file moved an error the file already had. The type-check oracle remembered each existing error by its offset, so once the first pass over a file had inserted text before one, the second pass took it for a new error and rejected every candidate it probed. - [#5](https://github.com/lelle/ts-capture/pull/5) [`8191939`](https://github.com/lelle/ts-capture/commit/81919397d5e964176eb18825def0aa6bd355692a) Thanks [@lelle](https://github.com/lelle)! - An observed object shape is no longer dropped because it happens to match a named type declared in a file the target does not import. `preferNamedInScope` rewrote the shape to that name, the name failed the scope check, and the valid structural annotation was lost with it. Only types the target file can name are now considered, so the shape is written structurally instead.

- [#5](https://github.com/lelle/ts-capture/pull/5) [`2e4ef6d`](https://github.com/lelle/ts-capture/commit/2e4ef6d4f0f19ed6a181c4fa0388c5dd9d355e14) Thanks [@lelle](https://github.com/lelle)! - An empty array observed inside an object no longer competes with a filled one at the same key. `{ lines: [] }` and `{ lines: [{ sku }] }` at one position used to merge to `{ lines: unknown[] | { sku: string }[] }`, which fails the type-check and was dropped; the empty observation now gives way, as it already did for a top-level array.

- [#5](https://github.com/lelle/ts-capture/pull/5) [`bcff6d1`](https://github.com/lelle/ts-capture/commit/bcff6d156e32be5dbe7b0f1ab673fe1fada34f28) Thanks [@lelle](https://github.com/lelle)! - `apply` no longer annotates a local, class field or callback parameter that TypeScript infers once the same run has typed the function it depends on. Redundancy used to be judged against the project as it was on disk, where an untyped callee returns `any`, so `const net: number = applyCoupon(...)` was written although `applyCoupon` got its return type in the same pass. A file's parameters and return types are now written first and its dependent sites are judged against the result; files are processed in import order so a callee typed in another file counts too. The second pass runs when `typecheckVerify` is on, which it is by default.

- [`8982422`](https://github.com/lelle/ts-capture/commit/898242297b7bdfd7174f26da4b03c2e49f442582) Thanks [@lelle](https://github.com/lelle)! - `node --import @ts-capture/core/register` now runs. Every file it instrumented stopped at `ReferenceError: __tscptr__ is not defined`. Node runs module loaders on a thread of their own, and the loader set up the runtime there, where the program cannot see it. The runtime and the write-back on exit now live in `register`, on the program's thread, and a function that returns a promise is typed with what the promise resolved to. The how-to now says that `register` needs a Node that runs `.ts` itself (22.18 or 23.6 and later), and what type stripping leaves out.

- [#5](https://github.com/lelle/ts-capture/pull/5) [`ad616fa`](https://github.com/lelle/ts-capture/commit/ad616fa77a990e16a7e4171ff8643f697e7bb281) Thanks [@lelle](https://github.com/lelle)! - A capitalised word inside a string literal, a capitalised property key and a capitalised parameter name are no longer mistaken for type names. Names are now read from the parsed type.

- [#5](https://github.com/lelle/ts-capture/pull/5) [`7ec6895`](https://github.com/lelle/ts-capture/commit/7ec6895af01955f114a3a8d150af59fd91b4d4d8) Thanks [@lelle](https://github.com/lelle)! - An object that appears more than once inside an observed value is now described every time, instead of as `unknown` from its second appearance on. The cycle guard remembered every object it had walked rather than only the ancestors of the current one, so two orders sharing one customer produced `customer: unknown` and annotations such as `lines: unknown | Line[]`. True cycles are still cut.

- [`d4046e9`](https://github.com/lelle/ts-capture/commit/d4046e98fe20c8694cf48fdb1bf485f76bf0e42d) Thanks [@lelle](https://github.com/lelle)! - A function passed as a value now gets a signature with all its parameters when some of them have a written type. `function k(a: string, b)` passed as a callback was typed `(b: number) => string`, which put `b` in `a`'s place; it is now `(a: string, b: number) => string`, with the written type kept as written. - [#5](https://github.com/lelle/ts-capture/pull/5) [`2883fbc`](https://github.com/lelle/ts-capture/commit/2883fbc7117ecce17e55dd3bd4cb2041d513d20f) Thanks [@lelle](https://github.com/lelle)! - Annotations read the way people write them. Only the text written to source changes; `types.json` and the comparisons apply makes before writing are unchanged.

- [`701f7a9`](https://github.com/lelle/ts-capture/commit/701f7a9eb62373edbb0f4f5e4e04a70c2bc38ae5) Thanks [@lelle](https://github.com/lelle)! - A union whose arms hold a function type is now taken apart correctly when observations are merged. The `>` of `=>` was read as closing a bracket, so `{ f: () => void } | string` counted as one arm. Among other things, an array of objects with a function member, such as `Array<{ a: null, f: () => void } | { a: number, f: () => void }>`, is now merged to `{ a: null | number, f: () => void }[]` like any other array of objects.

- [`b1f8b0b`](https://github.com/lelle/ts-capture/commit/b1f8b0b80e336bbeba29a37f765f6dfaab937140) Thanks [@lelle](https://github.com/lelle)! - `apply --telemetry` no longer counts observations that are not input to `apply`: those of a type you wrote, made for `verify` with `TS_CAPTURE_OBSERVE_ANNOTATED=1`, and the returns of callback parameters. They were listed as "Other (heuristic skip)" and lowered the emitted percentage, though what `apply` wrote was the same.

- [#5](https://github.com/lelle/ts-capture/pull/5) [`73c11fa`](https://github.com/lelle/ts-capture/commit/73c11fabd5a26d42efb980c4a6315a5f0c1128c5) Thanks [@lelle](https://github.com/lelle)! - `verify` now says where each mismatch is and what it could not check. A mismatch is printed as `file:line:col` with the declaration name, the declared type and the observed types, instead of a character offset. The totals line breaks the unverifiable positions down by reason (declared `any`, a generic the heuristic can only compare for equality, and so on). Three comparisons that were text artefacts no longer count as mismatches: an inferred `any[]` is unverifiable like `any`, polymorphic `this` is unverifiable, and an observed `undefined` matches an inferred `void`. The documentation now says what `verify` compares against: the type TypeScript has at each observed position, which is what it infers, since annotated positions are not instrumented.
